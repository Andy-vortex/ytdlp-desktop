YT-DLP 下载器 使用说明


开始

程序是一个文件夹：YT-DLP下载器.exe 要和旁边的 _internal 文件夹放在一起，不要单独复制或移动 exe。
双击 YT-DLP下载器.exe 启动。已经打开时再双击，会把窗口调到前面。
要快捷方式：右键 exe，"发送到 → 桌面快捷方式"。


五个页面（Ctrl+1～Ctrl+5 切换）

下载    粘贴链接，选格式和文件夹，开始下载；重试未完成。
采集    从网页里找出音视频链接，挑出要的加入下载；把采集设置存成订阅。
资料    历史、订阅、归档三个视图。
日志    下载、采集和更新的记录。"全部 / 错误"切换只看错误；"复制"复制全部记录；"⋯"里还有打开日志文件、清空显示。
设置    引擎、下载、新订阅、网络、界面、关于。改动立即保存。

左侧底部是程序状态：就绪、下载中、采集中、更新中、等待 mm:ss、已暂缓。
yt-dlp 有新版时出现"有新版"，点它到设置的引擎一栏。
不常用的动作在"⋯"菜单里；在表格、下载页的链接框、日志和选中的任务行上点右键，弹出的是同一个菜单。
页面空着时中间有下一步的按钮：下载页"粘贴"，资料 → 订阅"去采集"，资料 → 归档"去设置"（统一归档关闭时）。


下载链接

1. 复制链接，回到窗口。剪贴板里有新链接时会出现提示，点"添加"。
   也可以在链接框里粘贴（Ctrl+V）。App 的分享文字可以直接粘贴，程序会找出其中的链接。
2. 选格式。视频格式还可以选分辨率和"字幕"（有中文或英文字幕时嵌入）。
3. 要换文件夹，点文件夹按钮。
4. 点"开始下载"（链接框里按 Ctrl+Enter）。链接移到下面的任务列表；10 秒内点"恢复链接"可以放回。
5. 下载进行中，按钮变成"加入队列"：继续粘贴、点它，新链接排到后面。同一视频同一格式不会重复加入。

链接框的"⋯"：粘贴、导入 TXT…（Ctrl+O）、全选、清空。清空后按 Ctrl+Z 撤销。
TXT 支持 UTF-8、UTF-16、GB18030；以 #、;、] 开头的行忽略；不超过 5 MB。

播放列表
- 不勾"整个播放列表"时只下当前这一条；纯播放列表、搜索结果、频道链接只下第一项。
- 勾选后下载整个列表。YouTube 自动合辑（RD 开头的列表）始终只下当前一首。

格式
原始音频 · 保留源编码、M4A · AAC 原生、MP3 · 320 kbps、FLAC · 24 位、WAV · 32 位浮点、
MP4 · H.264（兼容优先）、MKV · 保留源画质。
转换格式不能找回源音频已经损失的细节。


任务列表

选中一行，行右侧的"⋯"：播放、在文件夹中显示、复制链接、查看原因、重试（已下载过的行是"仍然下载"）、移除。
双击已完成的行直接播放。Ctrl+E 在文件夹中显示最近保存的文件，F4 打开文件夹。
"停止"结束整个下载，也可以打断等待。已下载的片段保留，下次可以续传。
任务进行中关闭窗口，会先问是否停止。

已下载过
"跳过已下载过"默认开启：同一视频用同一格式下载过、文件还在原处，就不再下载，这一行显示"已下载过"。
要再下一次：这一行的"⋯ → 仍然下载"，或在设置里关掉"跳过已下载过"。文件被删除或移走后会重新下载。


文件命名

设置 → 下载 → 文件命名：标题（默认）、精简标题、标题 [视频 ID]。
精简标题只用于音频：去掉"歌手 - 歌名"后面的【】「」『』# 等装饰。
勾"整个播放列表"或开启"统一归档"时，文件名始终带 [视频 ID]，再次运行同一个列表会跳过已有的条目。
同名文件不会被覆盖，新文件名后加" (2)"" (3)"……
文件夹里已经有这一条所选格式的文件时，下载前就跳过，原文件不动。这条规则一直生效，与"跳过已下载过"无关。
"写入标签"写入标题、歌手和来源链接。"嵌入封面"不用于 WAV（WAV 不支持封面）。
临时文件一般放在工作文件夹，不出现在下载文件夹里。例外：整个播放列表、统一归档、命名为"标题 [视频 ID]"，
或下载文件夹和程序、工作文件夹都不在同一个盘时，临时文件留在下载文件夹里，完成后删除。
续传片段保留 7 天，7 天内重试同一条可以接着下载。


下载间隔与限流

稳健模式（默认开启）：两条下载之间随机等 10～20 秒，"整个播放列表"的每一条之间也一样。
间隔从上一条成功下载结束时算起；距离上一条已经超过 20 秒，或这是程序打开后的第一条时，不等待。
关闭稳健模式只取消这段间隔；出错重试和限流保护照常。
网络、分片、解析这类错误自动重试，最多 5 次。
网站返回 HTTP 429（请求太多）时整个队列暂停：先等 5 分钟，再次 10 分钟，通常最长 15 分钟；
网站要求更久时按网站的时间。同一链接最多再试 2 次，还不行就记为未完成，冷却后继续下一条。


未完成

失败、已停止、未开始、已暂缓的链接都留在未完成清单里，程序重启后仍在。
"重试未完成 (N)"（F5）重试全部；单条用"⋯ → 重试"。
任务区的"⋯"：重试未完成 (N)、清除未完成。清除前先确认，已下载的文件不受影响。
每条记住自己的格式、分辨率和文件夹；代理、cookies、稳健模式用当前设置。
以后同一链接同一格式下载成功，会自动从清单移出。


采集网页

1. 在采集页的链接框里粘贴网页链接，每行一个，最多 20 个。
2. 选模式。先用"普通网页"；链接或正文靠 JavaScript 加载时用"动态网页"（需要本机装有 Google Chrome）。
   动态网页可以选"滚动 0 次"～"滚动 5 次"（默认 0 次）加载后续内容；程序不会点登录、验证码或"加载更多"。
3. 页数（1～5 页）是每个网页最多翻几页：只跟随同一网站的 rel=next 链接，不遍历整个网站。
4. "CSS 范围"可以留空；填了（例如 article 或 .video-list）就只在这一部分里找链接。
5. 点"开始采集"（链接框里按 Ctrl+Enter）。点"停止"时已得到的结果保留。
6. 结果默认只显示媒体链接；筛选换成"全部链接"看全部。
7. 选中要的行（Ctrl 或 Shift 多选，Ctrl+A 全选），点"加入下载 (N)"。
   链接加进下载页的链接框并切过去，不会自动开始。
采集结果的"⋯"：加入下载 (N)、全选、导出链接…（TXT）、保存正文…（TXT 或 Markdown）、
归档正文（存进归档文件夹，不下载媒体）。
一次最多保留 2000 条链接。能采集到不等于一定能下载：登录状态不会带给下载，受 DRM 保护的媒体不解密。


订阅

建订阅：在采集页填好网页链接、模式、页数和 CSS 范围，点"订阅"。
订阅名取第一个网页链接，计划和两个开关取"设置 → 新订阅"的默认值，保存后切到"资料 → 订阅"。
改名用"⋯ → 改名…"；要改网页或范围，删除后重新订阅。

新订阅的默认值（只影响以后新建的订阅）
- 仅媒体链接：普通网页链接不算新增。
- 包含已有内容：关掉时，第一次成功检查只建立基线，以后新出现的才算新增。
- 计划：每 15 分钟、每小时（默认）、每天、仅手动。

用订阅
在"资料 → 订阅"选中一个订阅，下面是它的新增。选几条（Ctrl+A 全选），点"加入下载 (N)"；不要的点"忽略"。
新增一直保留，直到下载成功或被忽略。订阅从不自动下载。
"立即检查"马上检查一次。
订阅的"⋯"：立即检查、暂停（已暂停的订阅是"恢复"）、计划（每 15 分钟、每小时、每天、仅手动）、改名…、刷新、删除订阅。
删除订阅会一并删除它的新增和已见记录，删除后无法恢复；任务历史和已下载的文件保留。

定时检查
定时检查只在程序打开时运行，关闭后不在后台运行。
程序忙时顺延，重新打开后补查到期的订阅。计划一栏显示"待检查"，表示时间已到、还没轮到。
检查失败或被停止时，新增不会被清掉。
订阅只检查你设定的范围；更新太多超出页数、或需要登录时，可能漏掉内容。


历史（资料 → 历史）

每一次下载和采集都记在这里，最近的在上面。搜索框按标题或链接查找。
"继续"：
- 采集任务只再采失败和没处理的页，已完成的页不重采。
- 下载任务只下还没成功的链接，用当时的格式、分辨率和文件夹；代理、cookies、稳健模式用当前设置。
"查看结果"（双击或 Enter）：采集任务把结果载回采集页；下载任务把链接放回下载页的链接框。
历史的"⋯"：查看结果、继续、刷新。F5 也是刷新。这里的"继续"和下载页的"重试未完成"互不影响。


统一归档

打开：设置 → 下载 → 统一归档，再选归档文件夹。默认关闭，关闭时下载照常存到下载页的文件夹。
开启后，下载页的文件夹按钮显示归档文件夹，点它到设置里修改。
每条下载存到 归档文件夹\来源站点_来源ID\条目ID\：媒体文件夹、资料信息.json、阅读说明.txt；
从采集来的还有 网页正文.txt 和 网页正文.md；关联的转写稿放在转写稿文件夹。
资料信息记下原链接、来源、标题、作者、简介、发布日期和文件清单；网站没提供的不编造。
关闭统一归档时，已有的归档文件夹保持原样。
"资料 → 归档"：搜索标题、作者或来源；"打开文件夹"（双击或 Enter）。
归档的"⋯"：打开文件夹、关联转写稿…、刷新。"关联转写稿…"把 TXT、SRT、MD、VTT 复制进转写稿文件夹。
程序不做语音转写。
手动搬走归档文件夹后，要放回原位置才能直接打开旧条目。


设置

引擎
- "检查更新"只从 yt-dlp 官方 GitHub 稳定版下载，核对 SHA-256，确认能运行后才替换；失败时保留现有引擎。
  更新中按钮变成"停止"。
- "恢复内置引擎"只在使用更新过的引擎时出现。
- 每日检查（默认开启）：每天最多一次向 api.github.com 查询版本号，从不自动下载或安装。
- FFmpeg / ffprobe 和 Deno 随程序打包，不单独更新；版本在"关于"里。

下载
文件命名、统一归档、归档文件夹、写入标签、嵌入封面、跳过已下载过、稳健模式。见上文。

新订阅
仅媒体链接、包含已有内容、计划。见"订阅"。

网络
- 本次代理：留空就用当前网络；只在这次运行有效，不保存。
- YouTube cookies：见"常见问题"。

界面
- 完成提醒：窗口在后台时，下载进度显示在窗口标题上，任务结束时任务栏按钮闪烁。
- 识别剪贴板：回到窗口时提示还没添加的链接。不自动下载，不记录剪贴板内容。
- 外观：浅色、深色、跟随系统。
- 语言：跟随系统（Windows 的显示语言或区域格式是中文时用中文）、简体中文、English。
  改语言要重启：点"立即重启"，链接框和采集链接框的内容会带过去。文件名和文件夹名始终是中文。


快捷键

Ctrl+1～Ctrl+5     切换到 下载 / 采集 / 资料 / 日志 / 设置
Ctrl+V             粘贴链接（下载页，焦点不在输入框时）
Ctrl+Enter         开始下载 / 开始采集（在下载页或采集页的链接框里）
Enter              开始下载（下载页，焦点不在输入框时）
Enter              查看结果 / 打开文件夹（历史表 / 归档表）
Ctrl+L             跳到链接框（下载页）
Ctrl+O             导入 TXT…（下载页）
Ctrl+Z             撤销下载页链接框里的编辑，包括"清空"
Ctrl+E             在文件夹中显示最近保存的文件（下载页）
F4                 打开文件夹（下载页）
F5                 下载页：重试未完成；资料页：刷新
Ctrl+A             全选（采集结果表、订阅的新增表）
Shift+F10 / 菜单键  打开右键菜单（表格、下载页的链接框、日志、下载页选中的任务行）
Ctrl+C             复制日志里选中的文字


隐私

- 程序不收集使用数据。唯一的后台联网是每日检查（设置 → 引擎），可以关闭。
- 剪贴板内容和代理不保存；cookies 只保存文件路径，内容不进日志（设置 → 界面、网络）。
- 动态采集用独立的临时 Chrome，不读取你浏览器的登录和 Cookie。


数据放在哪

设置、未完成清单、日志、更新后的引擎和临时内容都在 %LOCALAPPDATA%\YtDlpDesktop：
  settings.json            设置
  failed-downloads.json    未完成清单
  download.log             日志（满 3 MB 轮换）
  library.sqlite3          资料库：历史、订阅、归档索引、下载记录
  engines                  更新后的 yt-dlp
  tmp、work、collect、cache  临时内容，自动清理
程序文件夹的 data 里有可写的 library.sqlite3 时，资料库用它。两处都写不了时，记录只放在一个临时文件里，关闭程序后删除。
默认下载文件夹是程序文件夹里的"下载文件"。

读不出的文件不删除、不覆盖，原样改名留在原来的文件夹，日志页写一行说明：
  settings.bad.json、failed-downloads.bad-<时间>.json、library.bad-<时间>.sqlite3、归档条目里的 资料信息.bad.json。
<时间> 形如 20261120-093000；名字已被占用时再加时间或序号。不需要时可以手动删除。
要备份：settings.json、failed-downloads.json、正在使用的 library.sqlite3、下载文件夹和归档文件夹。


从 1.x 升级

2.0.0 不读取 1.x 的历史、订阅和未完成清单，也不转换它们。第一次打开时，旧文件改名保留在原处，日志页各写一行：
  library.sqlite3        → library.bad-<时间>.sqlite3（在它原来的文件夹，%LOCALAPPDATA%\YtDlpDesktop 或程序文件夹的 data）
  failed-downloads.json  → failed-downloads.bad-<时间>.json
然后从空的历史、订阅和未完成清单开始。已下载的文件和归档文件夹不动。
设置里仍然有效的项目会保留（下载文件夹、归档、开关、外观等）；格式和分辨率回到默认，语言回到"跟随系统"。
订阅需要在采集页重新建立。1.x 没下完的链接在 failed-downloads.bad-<时间>.json 里，用记事本打开，把链接复制到下载页。
1.x 的归档条目不出现在"资料 → 归档"里；同一条再次归档时，旧的 资料信息.json 改名为 资料信息.bad.json，媒体文件不动。


常见问题

解析失败，或提示"Sign in to confirm you're not a bot"
这是 YouTube 对当前网络出口的临时验证，通常约 30 分钟后自行解除。多数情况不需要 cookies。
- 同一任务里其余 YouTube 链接标为"已暂缓"，留在未完成里；其他网站继续下载。
- 没有设置 cookies 时，程序自动安排重试（30 分钟后，之后 15 分钟、15 分钟）。
  任务区显示倒计时，可以点"立即重试"或"取消"。
- 换一个网络出口（例如换代理节点）通常也能恢复。

想马上继续：用 YouTube cookies
1. 在 Chrome 或 Edge 安装 yt-dlp 文档推荐的扩展"Get cookies.txt LOCALLY"。
2. 开无痕窗口，登录 YouTube（建议用小号），打开 https://www.youtube.com/robots.txt，导出 cookies.txt，关闭无痕窗口。
3. 设置 → 网络 → YouTube cookies，点"选择…"选这个文件，再重试。
文件必须是 Netscape 格式（第一行是"# Netscape HTTP Cookie File"）。
cookies 等同登录凭证，不要外传。程序只保存文件路径。过期后重新导出；点"清除"停止使用。

一直在"等待"
- 等待十几秒：稳健模式的间隔，可以在设置里关闭。
- 等待几分钟：网站限流（HTTP 429）的冷却，见"下载间隔与限流"。关闭稳健模式不会取消它。
两种等待都可以点"停止"打断，没下完的链接留在未完成里。

下载失败，原因写"页面不存在或无权访问"
网站回答了 403、404 或 410：链接失效、需要登录或有地区限制。

很多网站突然都下载不了
网站改版后需要新版 yt-dlp。到设置 → 引擎点"检查更新"。
