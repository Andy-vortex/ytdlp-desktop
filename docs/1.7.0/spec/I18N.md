## 1. Decisions (summary)

| # | Decision |
|---|---|
| D1 | One pure module `src/i18n.py` (standard library only, imports no app module) with `t(key, **values)`, `localize(text)`, `label(group, value)`, `choices(group)`, `init`, `detect`, `resolve`. | D2 | Languages `zh` (default, today's texts, byte-identical) and `en`. Any `zh-*` (also zh-TW, zh-HK, zh-MO) means `zh`. |
| D3 | Automatic rule: `zh` when the Windows display (UI) language **or** the user locale (regional format) is Chinese; otherwise `en`. | D4 | The language is fixed for the life of a process. A change in Settings is saved at once and applies after a restart; a one-click "立即重启 / Restart now" restarts the program (section 6). No live switch. |

| D6 | Stored and compared values keep their stored form (H2): Tk variables, tab ids, settings.json, failed-downloads.json and library.sqlite3 hold the Chinese / id values of 1.6.0; widgets show a localized label (section 7). |

| D8 | English wording is plural-free ("Links: 3"), uses the glossary terms and keeps the Microsoft YaHei UI font of 1.6.0. |
| D9 | README becomes bilingual (Chinese first, then an English section with a short user guide). `使用说明.txt` stays Chinese. No separate English manual in 1.7.0 (section 12). |
| D10 | On-disk names stay Chinese in both languages: `下载文件`, `资料归档`, `资料信息.json`, `网页正文.txt/.md`, `阅读说明.txt`, `转写稿`, `媒体`, `未命名`, `来源`, the exe `YT-DLP下载器.exe`. File *contents* written for the owner (archive readme, page-text headers, exports) use the running language. |

## 3. Module `src/i18n.py`

Standard library only (`ctypes`, `logging`, `os`, `re`, `string`, `threading`, `functools`). It
imports the map module `i18n_maps` and the catalog modules `i18n_core, i18n_common, i18n_shell,
i18n_download, i18n_log, i18n_settings, i18n_collect, i18n_library` (section 4) and nothing else of
the app, so every module (also `procutil.py`, `library.py`) may import it without a cycle.

### 3.1 Constants

```python
LANGUAGES = ('zh', 'en')
CHOICES = ('system', 'zh', 'en')          # settings.json 'language'
ENV = 'YTDLP_DESKTOP_LANG'                 # override: zh / en (also zh-CN, en-US, ...: by prefix)
```

### 3.2 State

`_current` (None until resolved). `language()` returns it, resolving lazily with
`resolve('system')` on the first call when `init` was never called (tests that build a `StudioApp`
directly, the collector worker). The value is read without a lock; it is written only by `init` and
`set_language`, which hold `_lock`.

### 3.3 Choosing

```python
def detect() -> str                        # 'zh' or 'en' from Windows (3.4)
def resolve(choice='system', environ=None) -> str
def init(choice='system') -> str           # app.py, once; sets and returns the language
def set_language(lang) -> None             # tests only (and init); clears the caches
def diagnostics(choice=None) -> dict       # {'ui_language': '0x0409', 'locale': 'zh-CN', 'choice': ..., 'env': ..., 'resolved': 'zh'}; resolves `choice` when given
def env_override(environ=None) -> str|None # 'zh' / 'en' when YTDLP_DESKTOP_LANG is set to a known value, else None
def stored_choice(prefs) -> str            # prefs['_extra'].get('language') when it is in CHOICES, else 'system' (5.1)
def store_choice(prefs, value) -> bool     # writes prefs['_extra']['language']; False for a '_held' session (5.1)
```

`resolve`: the environment value (case-insensitive prefix `zh` or `en`) wins; an unknown value is
ignored. Then `choice` `zh` / `en`; anything else (`system`, an invalid stored value) uses `detect()`.
`resolve(choice, environ={})` is the language the choice gives **without** the override; the
settings row compares that one (6.2).

### 3.4 Detection (Win32 through ctypes)

```python
kernel32 = ctypes.WinDLL('kernel32', use_last_error=True)
kernel32.GetUserDefaultUILanguage.restype = wintypes.WORD            # LANGID of the display language
kernel32.GetUserDefaultLocaleName.argtypes = (wintypes.LPWSTR, ctypes.c_int)
kernel32.GetUserDefaultLocaleName.restype = ctypes.c_int             # buffer of LOCALE_NAME_MAX_LENGTH = 85
```

- UI language is Chinese when `PRIMARYLANGID(langid) == LANG_CHINESE` (`langid & 0x3FF == 0x04`;
  0x0804 zh-CN, 0x0404 zh-TW, 0x0C04 zh-HK, 0x1004 zh-SG, 0x1404 zh-MO).
- User locale is Chinese when the locale name starts with `zh` (case-insensitive): `zh-CN`,
  `zh-TW`, `zh-Hans-HK`, ...
- Result: `zh` when either is Chinese, else `en`. A call that raises or returns 0 counts as "not
  Chinese" for that source; when **both** fail, the result is `zh` (the program's historical
  language). `detect` never raises.
- The functions are looked up through a module-level indirection (`_win32 = _Win32()`, with methods
  `ui_language()` and `locale_name()`) that tests replace (section 11.3).

### 3.5 Lookup: `t(key, **values) -> str`

1. `text = CATALOG[lang].get(key)`; when missing: `CATALOG['zh'].get(key)`; when also missing:
   the key itself. A missing key is logged once per (language, key) at WARNING on logger
   `YtDlpDesktop.i18n` (a set guarded by the lock); `t` never raises.
2. Placeholders are named (`{count}`, `{error}`), formatted with
   `string.Formatter().vformat(text, (), _Values(values))`, where `_Values` is a dict subclass whose
   `__missing__` returns `'{name}'` and logs once. Values are inserted with `str()`; catalog texts
   carry no format specs or conversions (the caller formats numbers: `f'{size:.1f}'`). A
   `ValueError` / `IndexError` / `KeyError` from a broken catalog text returns the unformatted text
   (logged once). Extra values are ignored.
3. Literal braces in a catalog text are doubled (`{{`); the catalog test checks that every text
   parses with `string.Formatter().parse`.
4. No plural forms exist: the API has no count-dependent selection (wording rule 8.3).

### 3.6 Core texts: `localize(text, keys=None) -> str`

Maps a canonical (Chinese) text produced by a core module, or stored by 1.5.1 / 1.6.0, to the
running language. Details in section 9. In `zh` it returns `text` unchanged (first statement; no
lookup), which keeps every 1.6.0 test and golden exact. Non-str input returns `str(input)` unless
`None` (then `''`). Never raises. `keys` (a tuple of key prefixes) restricts the templates that may
match; a caller that shows a text which may be user data (a stored job title, a collected page
title) passes the prefixes of the app-made forms only, so a media title that happens to equal a
core text is never translated (9.2, 9.3).

### 3.7 Stored values: `label(group, value) -> str`, `choices(group) -> list[(value, label)]`

`group` is one of the groups of section 7 (`'mode'`, `'format'`, `'resolution'`, `'naming'`,
`'appearance'`, `'language'`, `'interval'`, `'job_status'`, `'job_kind'`, `'link_kind'`,
`'collect_mode'`, `'collect_filter'`, `'library_tab'`, `'row_state'`). `label` returns the localized
label of a stored value; an unknown value returns `str(value)` (never raises, never logs: stored
data of another version may hold values this version does not know). `choices` returns the menu
order. The maps live in `i18n_maps.GROUPS` as `{group: {stored value: key}}` (section 4: owned by
L0, frozen in L1). The `format` group is keyed by the zh `Preset.label` (the value `self.format`
holds and `formats.by_label` reads), so a caller writes `label('format', preset.label)`.

### 3.8 Helpers

- `all_values(key) -> tuple`: the text of `key` in every language (zh first). `procutil.focus_window`
  uses it for the window title (section 7).
- `prefixes(tag) -> tuple`: the literal start (text before the first placeholder) of every key
  tagged `tag` (`'error'`, `'ok'`) in `i18n_log.TAGS`, in every language; `ui_log.classify` uses it
  (section 8.6).
- `sep(name)`: `t('common.' + name)` for joiners (`clause_sep`: zh `；` en `; `;
  `sentence_join`: zh `` en ` `).
- `join_sentences(parts) -> str`: zh joins with `；` (the stored form); en makes each part end with
  `.` (unless it ends with `.`, `…`, `?` or `)`) and joins with `sentence_join`. Used by `localize`
  for `；`-joined stored errors (9.2).

## 4. Catalog modules and ownership

Each catalog module defines `ZH = {key: text}` and `EN = {key: text}` with exactly the same keys,
sorted by key, one entry per line (clean line-based merges). `i18n.py` merges them at import; a key
defined in two modules is an error found by the catalog test (not at run time: the later module
wins).

| module | keys (by the file of their first use in the inventory) | owner in L1 |
|---|---|---|
| `i18n_maps.py` | no texts: `GROUPS` (3.7: stored value -> key, per group, in menu order), `LOCALIZE` (9.2: the key list, the older zh variants of `localize_zh_variants`, `NUMERIC` placeholder names, the per-placeholder recursion filters) | L0 (frozen in L1; a team that needs a change records it in its handoff and L2 applies it) |
| `i18n_core.py` | values of every key first used in a core file: `core.*`, `value.*`, `format.*`, `naming.*`, `app.title`, `filetext.*` of `library.py` | L1-C |
| `i18n_common.py` | keys used by two or more UI files: `common.*`, `table.*`, `dialog.filetype.*`, `error.*`, shared `dialog.*` | L0 (frozen in L1; changes go through the L2 merge) |
| `i18n_shell.py` | `studio.py`: `nav.*`, `shell.*`, `window.*`, shell `log.*` and `dialog.*` | L1-A |
| `i18n_download.py` | `ui_download.py`: `download.*` and its `log.*` / `dialog.*` | L1-A |
| `i18n_log.py` | `ui_log.py`: `log.subtitle` ... and `TAGS` | L1-A |
| `i18n_settings.py` | `ui_settings.py`: `settings.*` and the new language / restart keys | L1-B |
| `i18n_collect.py` | `collection_ui.py`: `collect.*`, its `log.*`, `dialog.*`, `filetext.export_*` | L1-B |
| `i18n_library.py` | `library_ui.py`: `library.*`, its `log.*`, `dialog.*` | L1-B |

Rules:
- The `ZH` value of a key is the exact 1.6.0 text; for an f-string it is the inventory's
  `zh_template` (the same text with named placeholders). The catalog test compares it with the
  source (11.1), so a Chinese text can no longer drift from the code.
- WP-L0 generates all eight catalog modules and `i18n_maps.py` mechanically from
  `strings-inventory.json` plus `new_strings_1_7_0` and `localize_zh_variants`
  (`verification/i18n_tool.py catalog`), so every L1 team starts with every key and every group map
  it needs and only edits values of its own modules. A key used only through a group map (for
  example `download.chip.*` via `row_state`, `value.link_kind.*` via `link_kind`) lives in the
  catalog of the file that shows it; the map holds only its name, so no team edits another team's
  file to change a label.
- The English values of the inventory are the starting point; a team may improve one in its own
  module when the glossary allows it; a glossary change goes through L2.

## 5. Language choice at start

### 5.1 settings.json (additive, H2)

`settings.py` is **not edited**: `defaults()` and `_CHECKS` keep their 1.6.0 content, so
`verification/test_core_paths_settings.py` (which lists the exact default dict and key set) stays
green and unchanged. The stored choice is a top-level key `language` that `settings.load()`
already treats as an unknown key: it arrives in `prefs['_extra']['language']`, and `settings.save()`
already writes every `_extra` key back at the top level (and every top-level key that does not
start with `_`).
- Read: `i18n.stored_choice(prefs)` returns `prefs['_extra'].get('language')` when it is one of
  `CHOICES`, else `'system'` (absent, invalid, a non-dict `_extra`, smoke mode's empty prefs).
- Write: `i18n.store_choice(prefs, value)` sets `prefs.setdefault('_extra', {})['language'] =
  value` and returns True; the next `save_settings()` (it copies `self.prefs`, `_extra` included)
  writes it. In a session that started with `settings._held` in prefs (settings.json could not be
  read at start), `settings.save()` writes only changed `_CHECKS` keys, so the choice would be lost:
  `store_choice` then returns False and the row shows `settings.language.held` and no restart button
  (6.2). This limitation is accepted: a held start is rare and already reported by 1.6.0.
- 1.5.1 ignores the key and drops it when it saves settings.json: after a session of 1.5.1 the
  choice is `跟随系统` again (on the owner's PC that is Chinese, as before). The file stays a flat
  UTF-8 object without BOM.

### 5.2 app.py (order)

1. Parse arguments (new hidden `--restarted-from PID`).
2. `--collect-worker`: unchanged (the worker emits canonical texts; no language needed).
3. `--self-test`: unchanged except an additive `result['language'] =
   i18n.diagnostics(i18n.stored_choice(settings.load()))` (read-only; it runs before step 4, so a
   self-test never waits for a `--restarted-from` pid).
4. When `--restarted-from` is given: `procutil.wait_exit(pid, timeout=20)` before
   `procutil.single_instance()` (section 6.3).
5. `applog.setup()`, hooks, cleanup threads as in 1.6.0.
6. `prefs = settings.load()` (already read for `appearance`); `lang =
   i18n.init(i18n.stored_choice(prefs))`; log once `language: <resolved> (choice <c>, env <e>, ui
   0x...., locale ..)` at INFO.
7. `import ui_theme` / `from studio import StudioApp` and the rest as in 1.6.0. Smoke mode
   (`--smoke-url`) calls `i18n.init('system')`, so the environment decides (tests: zh).

The UI modules never call `init`; they read `i18n.language()` lazily (3.2), which keeps import order
free and lets tests build a `StudioApp` without `app.py`.

## 6. When a change takes effect: restart, not live switch

### 6.1 Choice and reasons

A change of `语言 / Language` is stored at once and applied at the next start; the settings row then
offers a one-click restart. A live switch was rejected:
- About 540 keys are shown through some 400 call sites. Most widget texts are set once in the page
  builders (`build_*_page`), many are cached in widget state (`ui_theme.fit` keeps `_fit_text`,
  `wrap_to_width` keeps computed line breaks, the 50-row task pool keeps chip texts, `AppTable`
  keeps headings and empty texts, option menus and the segmented tab bar keep their value lists).
  A live switch would need a registry that re-applies every one of them, and a single forgotten
  widget leaves a mixed-language window that no test can prove absent.
- Rebuilding the pages instead would drop live state (link box, the running job's rows, collected
  links, selections, scroll positions) and would run next to the protected `set_busy` / `poll`
  machinery while a worker emits events.
- A restart costs one to two seconds, happens rarely (once after install, if at all), and leaves
  exactly one code path: build every page once in one language. Appearance stays a live switch (it
  only swaps colour pairs, which ui_theme already re-applies).

### 6.2 The settings row (card 提醒与界面, after 外观)

- Title `settings.language.title`, bilingual on purpose with the running language first: zh
  `语言 / Language`, en `Language / 语言` (a reader of either language finds the row; the inventory
  holds exactly these two values). Description `settings.language.text`, control: a
  `CTkSegmentedButton` with `跟随系统 | 简体中文 | English` (en: `System | 简体中文 | English`; the two
  language names are written in their own language in both catalogs). It shows the stored choice
  (`i18n.stored_choice(self.prefs)`), not the resolved language.
- `choose_language(value)`: `i18n.store_choice(self.prefs, value)` and `schedule_save()` (as
  `choose_appearance`), then `refresh_language_note()`:
  1. `store_choice` returned False (held session): the strip shows `settings.language.held`, no
     button.
  2. `i18n.env_override()` is not None (the environment variable fixes this session): the strip
     shows `settings.language.env_fixed`, no button. The choice is still saved.
  3. Else, when `i18n.resolve(value, environ={}) != i18n.language()` (the comparison ignores the
     environment on purpose), the strip shows `settings.language.restart_note` and the button
     `settings.language.restart` (立即重启 / Restart now); otherwise the strip is hidden. While
     `busy`, the button is disabled and the note reads `settings.language.restart_busy` (refreshed
     from `refresh_shell`, like `refresh_engine_controls`).
  At page build the strip is hidden (the stored choice is the one this process started with), so
  an untouched settings page looks the same in a sandboxed start (variable set) and a normal start;
  the strip appears only after `choose_language`, and `refresh_shell` only refreshes a visible
  strip's busy state.
- The language segment is not added to `self.controls`: changing the stored choice is allowed while
  busy (only the restart waits), so `set_busy` (protected, H3) needs no change for it.

### 6.3 The restart

`SettingsUI.restart_app()` (owned by L1-B, in `ui_settings.py`):
1. Return when `busy` or `closing`.
2. Keep the unsaved input. `save_settings` does not store the link box (`self.urls`), the collect
   page's start pages or the subscription name being typed, so a plain restart would silently drop
   them. `restart_app` writes them (only when at least one is not empty) to
   `restart-state.json` next to settings.json (`paths.settings_file().with_name(...)`, through
   `paths.atomic_write_text`): `{"version": 1, "created": <time.time()>, "pid": <os.getpid()>,
   "urls": "...", "collect_urls": "...", "subscription_name": "..."}`. The file holds links and a
   name only (no cookie contents, H6); 1.5.1 ignores it (H2). When it cannot be written
   (`OSError`), an askyesno `dialog.restart_unsaved.*` names the loss; "No" cancels the restart.
3. `save_settings()` (smoke mode: nothing is saved and no restart happens: the button is hidden in
   smoke mode).
4. `self.restart_launcher(procutil.relaunch_command(), procutil.restart_environment())`, where
   `restart_launcher(command, env)` defaults to `procutil.spawn_detached` and tests replace it (so a
   test sees the `env` argument). `relaunch_command()` returns `[sys.executable]`
   for the frozen exe, else `[sys.executable, '-X', 'utf8', <abs path of app.py>]`, plus
   `['--restarted-from', str(os.getpid())]`; no smoke arguments are carried over. `spawn_detached`
   uses `subprocess.Popen(command, cwd=paths.APP_DIR, env=env, close_fds=True,
   creationflags=DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP)`; `restart_environment()` is
   `os.environ.copy()` plus `PYINSTALLER_RESET_ENVIRONMENT='1'`. The PyInstaller 6.22.3 bootloader (pinned in
   requirements-build.txt) reads `_PYI_APPLICATION_HOME_DIR`, `_PYI_ARCHIVE_FILE` and
   `_PYI_PARENT_PROCESS_LEVEL` from the environment; without the reset variable the new exe would
   treat itself as a child of the old one and reuse its unpack state, and it must outlive its
   parent. This is the rule `procutil.process_environment` already follows for its other children
   (it is not reused here because it also prepends `paths.BIN` to PATH, which would grow on every
   restart). Everything else is inherited, so a sandboxed process stays sandboxed.
5. On success: `finish_close()`; the process ends and releases the single-instance mutex.
   On `OSError`: delete `restart-state.json` (when step 2 wrote it), message box
   `dialog.restart_failed.*` with the error; the window stays.
6. The new process waits for the old pid to exit (`procutil.wait_exit`: `OpenProcess(SYNCHRONIZE)` +
   `WaitForSingleObject`, at most 20 s; a pid that is gone returns at once) and then takes the mutex
   as usual. After a timeout it continues; `single_instance` then raises the old window and exits,
   which is the 1.6.0 behaviour for a second launch.
7. Under the test runner (`YTDLP_VERIFY_SANDBOX` set) the default launcher refuses with `OSError`
   unless a test installed its own: no test can start a real second program by accident (H7).
8. Restore (L1-B, `ui_settings.py`): the settings page builder schedules
   `self.after_idle(self.restore_restart_state)`, which runs after every page exists. It reads
   `restart-state.json` when the file exists, is younger than 120 s and is valid JSON of version 1,
   deletes it in every case (also when stale or broken), fills the three inputs only when they are
   still empty, and logs `log.restart_restored`. Nothing else reads the file; smoke mode skips the
   restore. No argument on the command line is needed, so `app.py` (L0) and `studio.py` (L1-A) do
   not change for it.

## 7. Persisted and compared values keep their stored form

Rule: a Tk variable, a dict key, a tab id or a stored field keeps the 1.6.0 value; only the widget
shows `i18n.label(group, value)`. In `zh` the label equals the value, so 1.6.0 behaviour is exact.

### 8.1 Replacing literals

- Every `ui` / `compared`-label / `filetext` literal of a UI module becomes `i18n.t(key, ...)` with
  the placeholders of the inventory (`t('download.link_count', count=len(result.urls))`).
- Module constants that tests or other modules read keep their **names and Chinese values** (H4):
  `ui_download.TITLE, STATE_LOOK, CLEARED_CHIP, CLEARED_DETAIL, FINISHED_UNFINISHED, CLEARED_METRICS,
  FINISHED_PREFIX, CLEARED_TITLE_SUFFIX, REASON_WORDS, HINT_DEFAULT, PLACEHOLDER, METRICS_IDLE,
  BOT_TEXT, BLOCKED_DETAIL, FOREIGN_TEXT, BOT_TEXT_COOKIES, PROXY_REASON, SKIPPED_TEXT, FORMATS`;
  `studio.TITLE`; `ui_settings.UPDATE_IDLE, APPEARANCE_LABELS`; `library_ui.INTERVALS, STATES,
  NOTHING_DONE, RESUME_*_LOG, HISTORY_NOTE ... PICK_ARCHIVE`; `collection_ui.MODE_*, FILTERS,
  STATUS_IDLE, NOTE_*, ADD_TEXT, BACKGROUND_NOTE, SUBTITLE` (test_polish_pages.py:184 reads
  `SUBTITLE`); `naming.LABELS`; `formats.PRESETS`. The code that *shows* one calls `t(<its key>)`
  instead of using the constant. Test-visible Tk variables keep their zh values too:
  `StudioApp.naming_label` (section 7).
- The parity table is **generated**, not hand-written: `i18n_tool.parity_table()` scans
  `verification/*.py` (ast) for every `<ui module>.<UPPER_NAME>` attribute reference and every
  `app.<name>.get()` compared with a CJK literal, keeps those whose module constant (or variable's
  initial value) contains CJK, and pairs each with the inventory key of its literal; the list above
  is the expected result on the 1.6.0 sources and the handoff of L0 records the generated table.
  The catalog test asserts `ZH[key] == constant` for each pair, so they cannot drift, and test 5
  (11.2) accepts exactly the generated set.
- Keys are never built from shown text. A key built from a stored value is allowed only through a
  group map (`label('row_state', state)`).

### 8.2 Composition

- No text is made by gluing translated fragments with Chinese punctuation. A sentence with variable
  parts is one template with named placeholders. Optional tails are their own templates
  (`download.hint.empty_lines`, `download.stats.final_skipped`) appended without a separator.
- Clauses joined at run time use `i18n.sep('clause_sep')` (`；` / `; `); two sentences of one
  line use `i18n.sep('sentence_join')` (`` / ` `), e.g. `collect.note.pages` + `collect.note.dynamic`.
- A text inserted into a template that came from the core is localized first:
  `t('download.metrics.wait', reason=i18n.localize(reason), time=time_text(seconds))`.

### 8.3 English wording rules

- Plural-free counts: "Label: n" or "(n)", with the label capitalised and parts joined by ` · ` —
  `Links: 3`, `Added: 2 · Duplicates skipped: 1`, `Retry unfinished (3)`, `Pages collected: 2 ·
  Links found: 40`, `Task finished · Succeeded: 3 · Unfinished: 1`, `Task started · Links: 3 ·
  MP4 · Save to D:\…`. Never "n link(s)", never lowercase "pages 3". A plural noun after a number
  is allowed only where the number is always 2 or more (`{title} and others ({count} links)`).
- One documented exception: the compact task-header stats (`download.stats.*`) use "n word" with
  an adjective or participle, numbers first and no colon — `12 done · 1 active · 37 waiting · 4
  unfinished`, `3 succeeded  /  1 unfinished  /  4 total  /  2 skipped`. These words need no plural
  and the form is about 5% narrower than "Label n" (10.5).
- Sentence case; page names and tabs in title case (GLOSSARY.md). Curly quotes for UI names, `→`
  for paths, `…` for ellipsis, no exclamation marks, no "please" except where the Chinese pleads.
- Short first: a one-line label states the fact, then the action ("Can't reach the site; check
  your network or VPN").
- Numbers keep the caller's formatting (`time_text`, `bytes_text`, `%m-%d %H:%M` dates): they are
  language-neutral.

## 9. Engine-side texts without touching H3 / H5

### 9.1 Principle

The core modules (`engine.py`, `collector.py`, `updater.py`, `naming.py`, `unfinished.py`,
`urls.py`, `formats.py`, `paths.py`) are **not edited** in the language adaptation. Their texts
(explain_error reasons, waiting reasons, log events, exception messages, update statuses,
`collect_status` / `collect_error` values, unfinished-list notes) stay the canonical Chinese of 1.6.0
in every language. Consequences:
- H3: no protected line changes at all (`Runner._run_once` with `下载间隔 / 重试等待`, the failed-list
  merge in `Runner.download`'s finally with `失败清单未能保存：…`, `StudioApp.set_busy`, the poll
  budget). The sanctioned-line permission is not needed.
- H5: the payloads are byte-identical; nothing is added.
- H2: everything the core stores (reasons in failed-downloads.json and the history, `last_reason`,
  `last_error`, job titles) stays Chinese, readable by 1.5.1, and is shown in the running language,
  also when the owner switches language later.
- Every 1.5.1 and 1.6.0 golden stays byte-identical (they record core output).
Exceptions with an owner: `library.py` gets `t()` for its `filetext` only (8.8, not protected);
`procutil.py` gets the two-title window search and the restart helpers (6.3). `settings.py` is not
edited at all (5.1).

### 9.2 How `localize` works

- `i18n_maps.LOCALIZE`: the keys whose zh text the core (or stored data) produces: every `core.*` and
  `value.*` key, `download.reason.proxy` (stored by `history_value`), `common.unfinished`; plus
  `VARIANTS`, older zh forms of a key found in stored data (`localize_zh_variants` of the inventory:
  `value.job_title.placeholder` also as `{count}条 · {mode}`, the form 1.5.1 wrote at
  studio.py:580 of the backup). Built once per language, lazily, under the lock:
  - `exact`: zh text -> key for templates without placeholders.
  - `patterns`: templates (and variants) with placeholders, compiled to anchored regexes
    (`\Z`, `re.S`): literal parts escaped; a numeric placeholder (`NUMERIC = count, code, seconds,
    line, page, pages, links, dropped, attempt, limit, status, minutes, length, size`) ->
    `(?P<name>\d+)` (`code` -> `-?\d+`, `size` -> `\d+(?:\.\d+)?`, the `{:.1f}` of
    unfinished.py:175); any other `{name}` -> `(?P<name>.+?)`, or `(?P<name>.+)` when it ends the
    template. Sorted by literal length, longest first, bucketed by the first literal character
    (templates that start with a placeholder go to a small shared bucket).
  - `RECURSE`: the captured values that are themselves core texts and are localized again, each
    with its own key filter: `reason` and `error` (all keys), `problem` (`core.unfinished.problem.`),
    `mode` (`value.mode.`), `name` (`value.subscription.untitled` only, so `订阅：未命名订阅` reads
    "Subscription: Untitled subscription"). Every other capture (`title`, `url`, `path`, `file`,
    `target`, `record`, numbers) is user data or a number and is inserted unchanged.
- `localize(text, keys=None)`: zh -> `text`. Else, considering only keys that start with one of
  `keys` (all keys when None):
  1. exact hit -> `t(key)`;
  2. else the first matching pattern -> `t(key, **values)` with the `RECURSE` values localized
     (depth at most 3);
  3. else, only when `keys` is None and the text contains `；`: split on `；`, localize every part
     (steps 1–4, depth + 1), and when at least one part changed return
     `i18n.join_sentences(parts)` (3.8). This runs after steps 1 and 2 because
     `value.subscription.interrupted` and `core.engine.waiting` contain `；` themselves. It covers
     the subscription `last_error` that collection_ui.py:376 stores as `'；'.join(errors[-2:])`;
  4. else token rules (`[代理]` -> `[proxy]` inside any line); else `text` unchanged.
  Results are cached (`functools.lru_cache(maxsize=4096)` keyed by language, `keys` and text).
- Raw engine output (`ERROR: [youtube] …: Sign in to confirm …`) matches nothing and passes
  unchanged; `explain_error`'s fallback (a cut engine line) passes unchanged too.
- Checked with `review\localize_proto2.py` on the regenerated inventory: the joined pair
  `网站返回 HTTP 403，可尝试动态模式或稍后重试。；页面超过 8 MB，请缩小采集范围。` gives "The site returned
  HTTP 403. Try dynamic mode or try again later. The page is larger than 8 MB. Narrow the collection
  scope."; `3条 · 音频 · MP3 320K` (1.5.1) and `1 条 · 音频 · MP3 320K` give "Links: 3 · Audio · MP3
  320K" and "Links: 1 · Audio · MP3 320K"; `周杰伦 等 群星 等 3 条` gives "周杰伦 等 群星 and others (3
  links)"; `检查中断；下次重试，不更新已见记录` gives its own English text (not split); a job title
  `检查未完成` with the job-title filter stays unchanged.
- Performance target: 10,000 mixed log lines localized in under 0.2 s on the owner's PC class
  (checked by a test with a generous bound of 1 s).
