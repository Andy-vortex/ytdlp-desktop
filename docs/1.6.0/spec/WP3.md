# WP3 - Design system (`ui_theme.py`)

Read: SPEC.md §3.13, §4; audit visual-1, visual-3, visual-4, visual-6, visual-7 (switch), visual-12 and the visual "missed" list (skeptic parts); prototype `docs/1.6.0/prototype/proto.py` and `shots/*.png` (widgets, switches, tabs).
Goal: one module that owns every colour, font, size and widget factory. Runs in parallel with WP0-WP2: it creates new files only, must not import `engine`, `paths`, `settings`, `_sandbox` or any other app module, and nothing in the app uses it until WP4. It must not edit any existing file (in particular not `src/progress.py`, which the 1.5.1 `studio.py` imports and which WP0/WP1 require to be byte-identical to the backup; its recolouring is WP4 step 3).

Owns: new `src/ui_theme.py`, new `verification/demo_theme.py`, new `verification/test_theme.py`. Nothing else.
Stack facts verified in customtkinter 6.0.0: `CTkButton(border_spacing, compound, anchor, text_color_disabled, image)`, `CTkSwitch(switch_width, switch_height, progress_color, button_color)`, `CTkCheckBox(checkbox_width, checkbox_height)`, `CTkSegmentedButton(selected_hover_color, ...)` (no `**kwargs`), `CTkScrollableFrame._parent_canvas/_scrollbar`, `ScalingTracker.get_widget_scaling/add_widget` (callback receives `(widget_scaling, window_scaling)`), `AppearanceModeTracker.add`, `ThemeManager.theme` (a dict with keys `CTk, CTkFrame, CTkButton, CTkLabel, CTkEntry, CTkCheckBox, CTkSwitch, CTkOptionMenu, CTkScrollbar, CTkSegmentedButton, CTkTextbox, CTkScrollableFrame, DropdownMenu, CTkFont`), `CTkTextbox.tag_config` (rejects `font`, and rejects a `(light, dark)` tuple as a colour: `TclError: invalid color name`).
Traps reproduced against customtkinter 6.0.0 (each has a rule below): a `CTkImage` built under one Tk root cannot be used under a second root (`TclError: image "pyimage1" doesn't exist`); `CTkEntry` never shows `placeholder_text` when a `textvariable` is given (`_activate_placeholder` requires `self._textvariable is None`); `grid_configure`/`pack_configure` are the raw tkinter methods and do not scale `padx`, only the overridden `grid()`/`pack()` do; `CTkLabel.configure(wraplength=...)` takes logical px while `winfo_width()` returns physical px; `CTkLabel.bind` binds both the inner canvas and the inner label, which report different widths; a `ttk.Treeview` defaults to `height=10` rows; a "transparent" `CTkFrame` paints its parent's colour as a rectangle.

## 2. Functions
```python

def apply_theme() -> None
def font(role='body') -> ctk.CTkFont
def label(parent, text='', role='body', **kw) -> ctk.CTkLabel
def button(parent, text, command=None, kind='soft', size='md', **kw) -> AppButton
def card(parent, **kw) -> ctk.CTkFrame
def chip(parent, text='', tone='idle', **kw) -> Chip
def tone_colors(tone) -> tuple            # (fg token, bg token)
def resolve(token) -> str                 # '#RRGGBB' of a (light, dark) token for the current appearance mode; a str passes through
def on_appearance(callback) -> None       # callback() after every appearance-mode change
def icon(code, tone='ink', size=16) -> ctk.CTkImage | None
def entry(parent, placeholder='', **kw) -> ctk.CTkEntry
def option_menu(parent, values, **kw) -> ctk.CTkOptionMenu
def checkbox(parent, text, **kw) -> ctk.CTkCheckBox
def switch(parent, text='', variable=None, **kw) -> AppSwitch
def textbox(parent, **kw) -> ctk.CTkTextbox
def scroll_area(parent, **kw) -> ScrollArea
def tabs(parent, names) -> Tabs
def table(parent, columns, selectmode='browse', empty='', height=None) -> ttk.Treeview
def empty_state(parent, text, icon_code=None) -> ctk.CTkFrame
def setting_row(parent, title, description='', control=None) -> ctk.CTkFrame
def fit(label, text) -> None
def full_text(label) -> str
def wrap_to_width(label) -> None          # keeps a CTkLabel's wraplength equal to its own width
def apply_ttk_styles(root) -> None
def set_page_cap(root, content, pages) -> None
```
Names must not shadow tkinter `Misc`/`Wm` methods (no `state`, `title`, `frame`, `size`, `focus`, `lift`...), because `StudioApp` will expose `label`, `button`, `card`, `table` as thin methods.

- `enable_dpi_awareness()`: on Windows, once per process (module flag), `ctypes.windll.shcore.SetProcessDpiAwareness(2)` inside `try/except (AttributeError, OSError)`. Must be called before the first Tk root exists; calling it later is harmless. Effect measured by the skeptic at 200 %: `tk scaling` 1.334 -> 2.668, ttk 10 pt line 19 -> 35 px, CTk layout unchanged.
- `apply_theme()`: idempotent. First call: `ctk.set_default_color_theme('blue')`, then update `ctk.ThemeManager.theme` in place, every colour as a `[light, dark]` list: `CTk.fg_color = BG`; `CTkFrame`: `fg_color SURFACE`, `top_fg_color SURFACE_ALT`, `border_color LINE`; `CTkFont`: `family FAMILY`, `size 13`; `CTkLabel.text_color INK`; `CTkButton`: `fg_color ACCENT`, `hover_color ACCENT_HOVER`, `text_color WHITE`, `corner_radius 8`; `CTkEntry` and `CTkTextbox`: `fg_color SURFACE_ALT`, `border_color LINE`, `border_width 1`, `corner_radius 8`, `text_color INK` (+ `placeholder_text_color FAINT` for the entry, `scrollbar_button_color SCROLL`, `scrollbar_button_hover_color SCROLL_HOVER` for the textbox); `CTkOptionMenu`: `fg_color MENU`, `button_color MENU_BUTTON`, `button_hover_color MENU_BUTTON_HOVER`, `text_color INK`, `text_color_disabled FAINT`, `corner_radius 8`; `DropdownMenu`: `fg_color SURFACE`, `hover_color ACCENT_SOFT`, `text_color INK`; `CTkCheckBox`: `fg_color ACCENT`, `hover_color ACCENT_HOVER`, `border_color CHECK_BORDER`, `border_width 2`, `corner_radius 5`, `text_color INK`, `checkmark_color WHITE`; `CTkSwitch`: `fg_color SWITCH_TRACK`, `progress_color SWITCH_ON`, `button_color ACCENT`, `button_hover_color ACCENT_HOVER`, `text_color INK`; `CTkScrollbar`: `button_color SCROLL`, `button_hover_color SCROLL_HOVER`; `CTkSegmentedButton`: `fg_color IDLE_SOFT`, `selected_color SURFACE`, `selected_hover_color SURFACE`, `unselected_color IDLE_SOFT`, `unselected_hover_color LINE`, `text_color INK`, `text_color_disabled FAINT`, `corner_radius 8`, `border_width 3`. It does not call `set_appearance_mode`; the caller does (`StudioApp.__init__`, the demo and every test call `ctk.set_appearance_mode('light')` before building a window, so a dark-mode Windows never renders the unfinished dark palette).
- `resolve(token)`: `token[1] if ctk.get_appearance_mode() == 'Dark' else token[0]` for a tuple/list, the string itself otherwise. Every plain-Tk or ttk API (`tag_config`, `ttk.Style`, `tk.Menu`, canvas items) gets its colour through it; CTk widgets keep receiving the tuples.
- `on_appearance(callback)`: appends to a module list. The first `apply_ttk_styles(root)` registers one `ctk.AppearanceModeTracker.add(handler, root)`; the handler re-runs `apply_ttk_styles(root)`, re-applies stripe and empty-hint colours of every live table, then calls each registered callback with no arguments (a callback that raises is logged with `logging.getLogger('YtDlpDesktop.ui')` and skipped). In 1.6.0 the mode never changes unless WP7 lands, but the hook exists from the start so that WP4's log tags are written once.
- `font(role)`: cached `CTkFont(family=FAMILY, size=SIZES[role], weight=...)`; created lazily (needs a root).
- `label`: defaults `font=font(role)`, `text_color=INK`, `height=LABEL_H[role]`; every keyword can be overridden (the old call sites pass `font=` and `text_color=`).
- `AppButton(ctk.CTkButton)`: kinds `primary` (ACCENT / ACCENT_HOVER / WHITE; disabled fill ACCENT_DISABLED, `text_color_disabled WHITE`), `soft` (ACCENT_SOFT / ACCENT_SOFT_HOVER / ACCENT_TEXT), `ghost` (`transparent` / ACCENT_SOFT / ACCENT_TEXT), `danger` (DANGER_SOFT / DANGER_SOFT_HOVER / DANGER); disabled soft/danger fill DISABLED_SOFT, ghost stays transparent, all three `text_color_disabled FAINT`. Height 36 (`sm` 28), `corner_radius 8`, `font('body')` (`caption` for `sm`), default `width=72` (a minimum; CTkButton grows to its text). Implementation rules from the skeptic: set `self._kind` before `super().__init__()`; `configure()` must work while `_kind` does not exist yet (CTkButton's constructor calls `configure(cursor=...)`); when `'state'` is in the kwargs add the matching `fg_color` with `setdefault` and make one `super().configure` call; after the constructor, if the state is `disabled`, call `self.configure(state='disabled')` (six existing buttons are created disabled). `button()` also accepts the legacy keyword `primary=True`.
- `card`: `CTkFrame(fg_color=SURFACE, corner_radius=12, border_width=1, border_color=LINE)`.
- `Chip(ctk.CTkLabel)`: `font('caption')`, `corner_radius=11`, `height=22`, `width=64`; `set(text, tone=None)` always updates the text and reconfigures colours only when the tone changes (progress updates call it many times per second). Tones: `idle` (MUTED on IDLE_SOFT), `info` (ACCENT_TEXT on ACCENT_SOFT), `ok`, `warn`, `danger`.
- `icon`: module-level `from PIL import Image, ImageDraw, ImageFont` (so PyInstaller collects them). Font `%WINDIR%\Fonts\SegoeIcons.ttf`, fallback `segmdl2.ttf`; draw `chr(code)` centred (`anchor='mm'`) on a 64 px transparent image, once in the light and once in the dark colour of the tone (`ink, muted, faint, accent, ok, warn, danger, white, side`); return `CTkImage(light_image, dark_image, size=(size, size))`; on any exception return None (callers then show text only). Caching: the rendered PIL images are cached by `(code, tone)` for the life of the process; the `CTkImage` objects are cached by `(code, tone, size)` only for the current default root - keep `_icon_root = tkinter._default_root` beside the cache and clear the `CTkImage` cache whenever `tkinter._default_root is not _icon_root` (a `CTkImage` holds `PhotoImage`s bound to the interpreter it was first drawn in; reusing one after that root was destroyed raises `TclError`, and tests do build a second root in one process). `font()` objects may be shared across roots (verified).
- `entry(parent, placeholder='', **kw)`: height 36, `font('body')`. The placeholder is implemented here, never with `placeholder_text` (which customtkinter ignores as soon as a `textvariable` is passed, and most entries of this app have one): a FAINT `CTkLabel` in the caption font, `fg_color` = the entry's fill, placed over the entry with `place(x=10, rely=0.5, anchor='w')`; a click on it focuses the entry; it is shown while the entry text is empty and hidden otherwise, updated from a trace on the `textvariable` (when given), from `<KeyRelease>` and from `<FocusOut>`. Passing `placeholder_text` together with `textvariable` raises `ValueError` in this factory. `option_menu`: height 36, `font`/`dropdown_font` body, `dynamic_resizing=False`. `checkbox`: 18 px box, `font('body')`. `textbox`: `font('body')`.
- `AppSwitch(ctk.CTkSwitch)`: `switch_width=38`, `switch_height=20`; knob `ACCENT` when on, `SWITCH_KNOB_OFF` when off, updated from a trace on the variable (programmatic `set()` must also recolour) - this is variant E of `shots/switches.png`; a white knob is broken on a white card.
- `ScrollArea(ctk.CTkScrollableFrame)`: `fg_color='transparent'` by default; one wheel notch scrolls 48-64 logical px (override the wheel handler; the stock one moves 20 physical px at 200 %); the scrollbar is removed with `grid_remove()` while `_parent_canvas.yview() == (0.0, 1.0)` and restored otherwise (re-check on `<Configure>` of the canvas and of the inner frame).
- `Tabs(ctk.CTkFrame)`: a `card` whose row 0 holds `CTkSegmentedButton(values=names, height=34, command=self.set)` (`sticky='w'`, `padx=16`, `pady=(14, 10)`) and whose row 1 (weight 1) stacks one transparent frame per name, each gridded `sticky='nsew'` with `padx=6, pady=(0, 6)` (a transparent frame paints the card colour as a rectangle; without the inset it covers the card's 1 px border and squares off the two bottom corners of a radius-12 card). Page builders therefore use an inner padding of 10 inside a tab frame to keep the 16 px visual margin. Methods `add(name) -> frame` (returns the existing frame; kept for `CTkTabview` compatibility), `tab(name)`, `set(name)` (raise + select), `get()`.
- `table`: `columns` = tuples `(key, title, width)` or `(key, title, width, stretch)` in logical px. Builds `container = CTkFrame(fg_color=SURFACE, corner_radius=8, border_width=1, border_color=LINE)`, a `ttk.Treeview(show='headings', style='App.Treeview')` gridded with `padx=(4, 0), pady=4`, headings and cells `anchor='w'`, a `CTkScrollbar(width=14)` that hides itself when the view is `(0, 1)`, a centred empty-hint label (explicit `fg_color=SURFACE`), tag `odd` (STRIPE). The returned tree gets attributes/methods: `container` (the caller grids or packs it), `fill(rows)` (`rows` = iterable of `(iid, values)`; clears, inserts, stripes, toggles the hint, restores the selection when the iid still exists), `restripe()`, `set_empty(text)`. `height` (rows) is passed to the Treeview; when None the factory passes `height=4`. A Treeview's default of 10 rows would request about 350 logical px and make a page ask for more height than the 1000x740 window has; tables are always gridded `sticky='nsew'` in a weighted row and stretch to the space they get, so the small request costs nothing.
- `apply_ttk_styles(root)`: `S = ScalingTracker.get_widget_scaling(root)`; colours through `resolve()`; `style.theme_use('clam')`; for the style names `App.Treeview` and `Collect.Treeview` (the latter keeps the not-yet-migrated pages readable): `configure(font=(FAMILY, -round(12 * S)), rowheight=round(32 * S), background=SURFACE, fieldbackground=SURFACE, foreground=INK, borderwidth=0, relief='flat')`; `layout([('Treeview.treearea', {'sticky': 'nswe'})])`; `map(background=[('selected', SELECT)], foreground=[('selected', INK)])`; `<name>.Heading`: `configure(font=(FAMILY, -round(12 * S)), background=SURFACE_ALT, foreground=MUTED, relief='flat', borderwidth=0, padding=(round(10 * S), round(7 * S)))`, `map(background=[('active', IDLE_SOFT)], relief=[('active', 'flat')])`; `<name>.Cell`: `configure(padding=(round(10 * S) - 4, 0))` (aligns cell text with heading text). The first call for a root registers `ScalingTracker.add_widget(callback, root)`; the callback re-runs the styles and rescales the column widths of every live table (keep a `WeakSet` of trees with their logical widths). `table()` calls `apply_ttk_styles(parent.winfo_toplevel())` when it has not run for that root.
- `empty_state`: transparent frame with a centred FAINT icon (when available) above a MUTED caption.
- `setting_row`: transparent frame, column 0 (weight 1): body title, MUTED caption description (`sticky='ew'`, `justify='left'`, `anchor='w'`) kept wrapped to its own width by `wrap_to_width`; column 1: right-aligned `control_area` frame (attribute). When `control` is given it is called as `control(row.control_area)` and the result is packed.
- `wrap_to_width(label)`: binds `<Configure>` once (`add='+'`). The handler ignores `event.width` (the callback fires for the inner canvas and for the inner label with different widths; setting `wraplength` from it oscillates forever - 1070 callbacks in 2.5 s measured) and computes `new = max(1, int(label.winfo_width() / S) - 2)` from the outer widget (`wraplength` is in logical px, `winfo_width()` in physical px; using the raw width doubles the wrap width at 200 %), then calls `label.configure(wraplength=new)` only when `new` differs from the value stored on the label (settles after about five callbacks). Public: WP5 uses it for `history_note`.
- `fit(label, text)`: store the full text on the label; when `label.winfo_width() <= 1` (withdrawn test windows) set the full text; otherwise cut to the label width with a trailing `…`, measuring with `tkinter.font.Font(family=FAMILY, size=-round(px * S))` against the outer `label.winfo_width()` (never `event.width`), and reconfigure the text only when the cut text changes; bind `<Configure>` once (`add='+'`) to refit. Precondition (documented in the docstring): the label is gridded `sticky='ew'` in a column with weight > 0; in a column without weight the label keeps its full text width and pushes its siblings out. `full_text(label)` returns the stored text (or `cget('text')`).
- `set_page_cap(root, content, pages)`: `pages` = `{page_frame: max_width | None}`; on `<Configure>` of `content` (coalesced with `after_idle`) set `page.grid(padx=(0, max(0, round(w - max_width))))` for capped pages, `w = content.winfo_width() / S`. It must be the customtkinter `grid()` override, which scales `padx` and remembers it for later scaling changes; `grid_configure` is the raw tkinter method and would apply half the padding at 200 % (the page would be capped near 1700 px instead of 1080). `grid()` keeps the other grid options (`sticky` verified). Call it only when the value changed; never change anything but that padding.
