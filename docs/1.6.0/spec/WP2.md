## G. Queue model in `Runner.download` (two steps)
Internal `QueueItem` (plain class): `index, url, origin, options, preset, key, multi, state='pending', ran=False, error='', reason='', title='', path='', media_keys=[], files=0`; `multi = urls.multi(url, options.playlist)`.
Item states (SPEC §3.8): `pending` -> `active` (set by `_next()`) -> `done | failed | blocked | stopped | unstarted`; or `pending` -> `skipped | blocked` without running; whatever is still `pending` at the end becomes `unstarted`. `ran` is True once `_run_once` was called for the item.
Runner attributes: `items`, `inbox`, `opened`, `closed`, `base_options`, `queue_lock`, `blocked` (bool), `origins` (public dict cleaned URL -> original, set by the caller, default `{}`), `_archives` (dict `archive_root` -> `Archive`), class attribute `last_media_end = None`, `Runner.reset_pacing()`, module constant `PACE_SECONDS = (10, 20)`.
Locks: `queue_lock` (a `threading.Lock` created in `__init__`) guards only `items`, `inbox`, `opened`, `closed`. `Runner.lock` keeps guarding `process` only: `_run_once` holds it across `mkdtemp` + `Popen` (engine.py:300-306), and `enqueue` is called from the Tk thread, which must never wait for a process start. Nothing is emitted while `queue_lock` is held.

## H. `library.py`
- `tx()` context manager: like `db()` but executes `BEGIN IMMEDIATE` first; use it in `change_job`, `collection_event`, `download_event`, `finish_subscription`, `extend_job`, `rename_job`, `record_download`.
- No nested transactions: `Library` opens a new connection per call (library.py:97-105), so a public `tx()` method called while another `with self.tx()` of the same thread is open waits on the app's own write lock and fails with `database is locked` after the 20 s timeout (reproduced with two connections). Therefore the work is done by private helpers that take the open connection or the loaded dict - `_record_download(db, keys, format, url, title, path, job)`, `_extend(data, urls, overrides=None)`, and a plain `UPDATE jobs SET title=?` on `db` - and the public `record_download` / `extend_job` / `rename_job` only open their own `tx()` and call them. Inside `download_event` every write goes through its own `db`. Rule for the whole class: no `Library` method calls another public `Library` method while its own `with self.tx()` / `with self.db()` block is open.
- Schema: add the `downloads` table to the `executescript`.
- `record_download(keys, format, url, title, path, job)`: `INSERT OR REPLACE` one row per distinct key. `find_download(keys, format)`: newest row whose key is in `keys`; returns its columns plus `exists = Path(path).is_file()`; None when absent.
- `extend_job(job, urls, overrides=None)`: append URLs not yet in `data['options']['urls']`; merge `overrides` (`{url: options dict}`) into `data['options'].setdefault('overrides', {})`, so that a later resume gives enqueued links their own format and folder. `rename_job(job, title)`: `UPDATE jobs SET title=?`. `history(limit=300)`: `ORDER BY updated DESC LIMIT ?`.
- `download_event(job, kind, value)`: every key marked "+" in SPEC §3.8 is read with `.get()` and its absence is not an error (`test_library.py:125-128` calls it with `dict(url=…)` and `dict(success=True)` only; the 1.5.1 UI forwards only `item/file/item_done/done`). Per kind:
  - `item`: also stores `current_key = value.get('key')`, `current_format = value.get('format')`, `current_origin = value.get('origin')`, `current_multi = bool(value.get('multi'))`.
  - `title` (str): on the first one of a job set the job title to the title, or `f'{title} 等 {n} 条'` when the job has n > 1 URLs, and remember `data['titled'] = True`.
  - `media`: keys = the media key `f'{extractor_key.lower()}:{id}'` (unless the extractor is `Generic` or the id is empty) plus `current_key` only when it is set and `current_multi` is False. A playlist, search or channel link stands for many files; recording its link key would make `find_download` report the whole list as downloaded after the first entry (`PRIMARY KEY(key, format)`). No keys or no `current_format` -> nothing recorded. Then `_record_download(db, keys, current_format, data.get('current'), title, filepath, job)`.
  - `queued`: `_extend(data, value.get('urls') or [], value.get('overrides'))`.
  - `item_done`: on success as today, and additionally clear subscription entries for `identity(current_origin)` when `current_origin` is set. When `value.get('skipped') == 'downloaded'` (no `item` event preceded it, so `data['current']` is not this link): append `value.get('url')` to `data['completed']` and run `UPDATE entries SET pending=0 WHERE key=?` for `identity(url)` and, when present, `identity(value.get('origin'))` - a subscription link that is already on disk must leave 待处理 and must not be offered again by a resume. When `value.get('error')` append it to `data['errors']` (keep the last 20).
  - `done`: status `partial` also when `value.get('blocked')`.
  - Unknown kinds are ignored.
